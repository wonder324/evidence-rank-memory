# 网关输出与 Add 重试修复

基于公开 v0.4.0 提交 `fffd6f0b29de873142706e0007937c7d9eaeef2a`。`SOURCE_MANIFEST.json` 记录该原始导入快照，不代表本修复后文件的哈希。

## 改动

- 识别实测的 `<escape` 包装、JSON 数组括号在字符串外的反斜杠转义，以及有限的包装结束标记。也接受完整的 JSON 代码块。JSON 字符串内部的路径、转义、文字及事实值保持不变。
- 拒绝无法解析、缺少 facts 数组、输出截断或模型拒绝的响应。不用正则猜测或生成事实，不调用额外模型来修复内容。
- 增加可选 `LLM_EXTRACT_STRICT=1`。已启用的抽取器失败时返回 HTTP 503 与 Retry-After，在此次 Add 写入前退出。默认 0 保留原先的失败回退行为。
- 已成功的 request_id 在再次调用模型前检查；保留原来的 user_id/session_id 冲突规则及事务内二次检查，不修改数据库结构。
- 记录 Add 请求标识的 SHA-256 前缀、耗时和状态，不记录记忆正文或凭据；模型错误日志不包含原始响应。

模型 ID、提示词、向量模型、融合权重、检索排序、数据命名空间均未改变。包装兼容与严格失败行为仍属于实现变更，并可能影响新写入的事实，因此进行中的评测需由组织方确认如何恢复。该修复不会自动补写过去已成功但模型抽取失败的 Add。
