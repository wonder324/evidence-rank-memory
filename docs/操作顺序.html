Agent Memory Challenge 操作顺序

开源方法榜 · 系统 evidence-rank-memory 0.1.0 · 整理日期 2026-10-06
材料截止 2026-10-31 23:59（北京时间）。评测停止 2026-11-04 23:59。正式评测这一轮只有一次。

总原则。组别是开源方法榜。先在本地把已知的检索问题改完，并接上真实的 gpt-4o-mini，再把代码推进公开仓库，然后部署到公网。外网接口可用之后再填报名表。报名表提交时固定版本和 commit。正式评测受理之后，不能因为分数不理想更换版本，也不能撤回。向量用 text-embedding-v4。Add 阶段必须调用 gpt-4o-mini，不能用 qwen-plus 顶替。奖金只发给开源方法榜。

已经完成、这份顺序里不用重做的部分

  • 本地接口 http://127.0.0.1:8080 的 /health、/add、/search 可用。
  • 阿里云百炼密钥已写入 .env 的 DASHSCOPE_API_KEY，向量接口曾返回 200。
  • 向量已配置为 text-embedding-v4。gpt-4o-mini 的密钥还没有，Add 阶段目前只有规则抽取。
  • 接口契约测试已通过。13 道合成题在哈希向量上的 MRR 为 1.0。这不是榜单分数。
  • README 里有可粘贴的报名说明。Docker 与 deploy/Caddyfile 已在项目中。

  1. 修中文抽取

    目的：去掉错误的「当前住址」。句子「我以前住在杭州，现在住在南京」会被通用规则切成主语「我以前」、地点「杭州」，并标成 status=current。正确的当前住址南京仍然排第一，但这条噪声可能干扰平台的答题模型。

    操作

    打开 app/extract.py。搬家句式大约在第 120 行，模式是「我以前住在……，现在住在……」。它已经会抽出用户的杭州和南京。同一次循环后面，通用规则「某某住在某地」（约第 96 行，模式 ([汉字]{2,8})住在）又会把「我以前」当成另一个人。

    改法：这句已经命中搬家模式时，跳过后面的通用「某某住在某地」规则。杭州只保留为 status=previous，南京保持 status=current。不要把千问的模型名改成 gpt-4o-mini。

    改完后的检查

    重启本地服务。用一个新的 user_id 写入这句话，再搜索「我现在住在哪里」。第一名应包含「南京」且为 current。结果里不应再出现「我以前 residence = 杭州 (status=current)」。

    cd /Users/wonder/Desktop/agent-memory-challenge
source .venv/bin/activate
set -a && source .env && set +a
# 先停掉旧的 python -m app，再启动
python -m app

    服务在另一个终端保持运行。再开一个终端执行写入和检索，user_id 用 fix-city，request_id 不要和以前重复。

  2. 用 text-embedding-v4 重拟合权重

    目的：搜索时有十路分数（BM25、向量、重叠、实体、原文、时间、事实类型、二跳、选项、档案）。当前 models/fusion_weights.json 是用哈希向量拟合的。换成 text-embedding-v4 后，向量这一路的数值分布变了，需要在真实向量上重新选择权重。

    操作

    打开 train/fit_weights.py。把 Settings(..., embedder="hash", ...) 改成 embedder="dashscope"。把写入 JSON 的 "embedder": "hash" 改成 "embedder": "dashscope"。确认 .env 里 EMBEDDING_MODEL=text-embedding-v4，并且 DASHSCOPE_API_KEY 已填写。

    若第 1 步之后仍有排错的句子，把该句加进 episodes()，写上问题和答案里必须出现的词。

    cd /Users/wonder/Desktop/agent-memory-challenge
source .venv/bin/activate
python -m train.fit_weights

    脚本使用 data/train/memory.db，不会覆盖正在服务的数据库。它只用这 13 道人造题，不能把评测流量拿来训练。结束时看 train_mrr 和 holdout_mrr。1.0 表示这些题的答案都排在第一。若已经全对，权重数字可能几乎不变。改完权重后要重启 python -m app，服务才会读到新文件。

  3. 本地再测一遍，然后冻结代码

    目的：确认接口仍然符合比赛契约，并且你关心的中文事实已经排对。这一步通过之后，才把这份代码当成要上公网的版本。

    cd /Users/wonder/Desktop/agent-memory-challenge
source .venv/bin/activate
python scripts/contract_check.py

    应打印 contract check passed。然后用新的 user_id 检查三条：

    • 「我现在住在哪里」的第一名是南京，status=current。
    • 「我以前住在哪里」能找到杭州，并且是 previous，而不是另一条 current。
    • 换一个 user_id 搜索，结果是空的 {"data":[]}。

    本地通过只说明逻辑可用。平台不接受 127.0.0.1。

  4. 买香港机器和域名，部署 HTTPS

    目的：让平台能从公网调用 /health、/add、/search。不要买中国大陆的服务器。大陆机器用域名开放 80 和 443 必须先做 ICP 备案，审核通常一到三周，赶不上 10 月 31 日。香港机器不需要备案。

    购买

    • 阿里云轻量应用服务器，地域选中国香港，系统 Ubuntu 22.04，规格 2 核 4 GB，时长买到 11 月中旬。
    • 一个域名，例如 .com。解析不要开 CDN 代理，A 记录必须直接指向这台机器的公网 IP。
    • 防火墙只放行 22、80、443。不要把 8080 暴露到公网。

    确认解析

    dig +short 你的域名

    输出必须是那台机器的公网 IP。

    上传项目

    在 Mac 上执行。会带上 .env，不要把这个文件提交到 git。

    rsync -av --exclude .venv --exclude data --exclude .git \
  /Users/wonder/Desktop/agent-memory-challenge/ \
  root@你的域名:/opt/memory/

    在服务器上启动

    curl -fsSL https://get.docker.com | sh
cd /opt/memory
docker build -t evidence-rank-memory .
docker run -d --name memory --restart unless-stopped \
  --env-file .env -p 127.0.0.1:8080:8080 evidence-rank-memory

    安装 Caddy

    apt update
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
apt update
apt install -y caddy
export DOMAIN=你的域名
cp /opt/memory/deploy/Caddyfile /etc/caddy/Caddyfile
systemctl reload caddy

    deploy/Caddyfile 会把 HTTPS 反代到本机 127.0.0.1:8080，并由 Caddy 向 Let's Encrypt 申请证书。密钥放在请求头 Authorization: Bearer，不要写进网址。

    从 Mac 验收

    cd /Users/wonder/Desktop/agent-memory-challenge
set -a && source .env && set +a
curl -s https://你的域名/health
curl -s https://你的域名/add \
  -H "Authorization: Bearer $MEMORY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"request_id":"public-1","user_id":"me","session_id":"s1","messages":[{"role":"user","content":"我现在住在南京。"}]}'
curl -s https://你的域名/search \
  -H "Authorization: Bearer $MEMORY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query":"我现在住在哪里？","user_id":"me","top_k":5}'

    完成标准：/health 返回 status=ok、系统名 evidence-rank-memory、版本 0.1.0。/add 返回 success true。/search 第一条证据包含南京。

    公网是另一份拷贝。本地还可以继续运行 http://127.0.0.1:8080。两边数据库互不相通。本地再改代码，不会自动更新公网。要更新线上，必须重新上传、构建镜像并重启容器。填表之后就不要再换算法。

  5. 填写报名表

    打开 https://agentmemoryleaderboard.ai/evaluation，由你本人提交。

    栏位填写内容
    系统名称 / 版本evidence-rank-memory / 0.1.0
    赛道 / 组别文本记忆 / 开源方法榜
    公开仓库GitHub 地址和固定 commit。没有 commit 不能报这一榜
    三个地址https://你的域名/health 、 /add 、 /search
    鉴权Bearer。密钥等于服务器 .env 里的 MEMORY_API_KEY
    方法、容量、原创声明粘贴 README「报名时可以直接粘贴的说明」
    联系人、机构或团队你自己的真实信息

    平台不接受只交仓库或 Docker，也不会替你部署。开源方法榜要同时提供公开仓库、固定 commit，以及已经在调用 gpt-4o-mini 的线上 Add 接口。仓库不能代替接口。

  6. 拿到 Eval Key 之后先冒烟

    审核通过后，平台签发 Eval Key。这个 Key 和 MEMORY_API_KEY 不是同一个。不要把任何一个 Key 写进网址、仓库、截图或群聊。

    先运行冒烟，确认平台侧能完成 Add 和 Search。冒烟每小时最多 1 次，每个赛道最多 30 次。冒烟用来确认已经固定的接口，不要在冒烟期间更换抽取规则或权重。

  7. 10 月 24 日至 27 日打一次正式评测

    每个赛道正式评测最多 2 次。第二次要等第一次跑完满 30 天，所以这一轮只有一次。正式评测大约需要 0.5 到 2 天。这段时间香港机器不能关机，容器要保持运行。

    建议窗口是 2026-10-24 到 2026-10-27。材料必须在 2026-10-31 23:59 前提交。评测在 2026-11-04 23:59 停止。正式评测受理后，不能因为结果不理想更换版本或撤回。

    top_k 按平台正式要求为 100。服务默认同时处理 8 个请求，超出返回 HTTP 429，Retry-After 为 2 秒。

  8. 评测结束后 30 天内删除评测数据

    在服务器的项目目录执行 README 中的清理命令：

    python -c "from app.config import get_settings; from app.embedder import Embedder; from app.store import MemoryStore; s=get_settings(); MemoryStore(s, Embedder(s), s.weights()).purge_all()"

    若线上是 Docker，在容器能读到同一份数据目录时执行，或删除该容器使用的数据库文件后重启。评测流量不能留作下一轮训练数据。
